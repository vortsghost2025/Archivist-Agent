Yes. This should become a **natural promotion protocol**, not something you and I manually catch every time.

The core problem is:

```text
lanes finish at different times
older valid work arrives after newer canonical work
agent thinks “my work is correct”
but system needs “is my work still current?”
```

So the missing process is not more verification. It is **pre-promotion freshness/adoption gating**.

## The rule you need

Before any lane promotes a snapshot, patch, graph mutation, summary, or broad verification result, it must pass:

```text
CANONICAL_PROMOTION_GATE
```

Minimum checks:

```text
1. What canonical artifact did I start from?
2. What was its hash / timestamp / generation?
3. What is the current canonical artifact now?
4. Has canonical state advanced since I started?
5. If yes: do not apply; rebase or mark stale.
6. If no: promote with evidence.
```

That catches the Library case automatically.

