Layer 0 — Already Done ✅
Signed message passing, lane-worker (--watch --apply), inbox-watcher, relay-daemon, heartbeat, AI review router, convergence protocol spec, sovereignty scanner, recovery test suite (10/11).

Layer 1 — Headless Daemon Deployment (Prerequisite for everything)
#	Task	Why
1.1	Deploy systemd services for all 4 lanes on VPS — worker + relay + heartbeat per lane repo (Archivist-Agent, SwarmMind, Kernel, Library)	Only Library has services currently
1.2	Crash recovery verification — Restart=always + StartLimitBurst=5, verify state persists across restarts	Daemons must survive VPS reboots
1.3	Unified log aggregation — journalctl → structured JSON, or stderr → /var/log/lane-{name}.log with rotation	Need logs for debugging autonomous failures
1.4	Tailscale connectivity watchdog — periodic tailscale status check, auto-reconnect on drop	VPS is Tailscale-only; split brain if Tailscale drops
1.5	Repo clone + sync on VPS — all 4 repos cloned, SSH deploy keys configured, git pull on file-watch or timer	Each lane repo needs to be present for its worker
Result: All 4 lanes running as systemd services on VPS, surviving reboots, logging coherently.
---
Layer 2 — Continuous Loops (Detection)
#	Task	Why
2.1	Sovereignty enforcement loop — refactor scanner from pre-commit hook into a daemon (sovereignty-enforcer.js --watch) that runs every N minutes	Currently only catches violations at commit time; autonomous system needs continuous enforcement
2.2	Health check loop — health-monitor.js that runs recovery-test-suite periodically, publishes results to lanes/broadcast/health.json	Replaces manual test runs; feeds into alerting
2.3	Convergence loop — convergence-daemon.js that periodically scans for pending proposals, advances them through REVIEW → AMEND → CONVERGE → RATIFY	Currently proposals sit until manually pushed
2.4	Graph drift detector — periodic snapshot comparison, emits contradiction alerts when authority edges shift	Catches knowledge graph decay
2.5	Systemd services for Layer 2 daemons — one service per loop	Persistence
Result: System continuously detects problems, advances governance, and publishes health state.
---
Layer 3 — Self-Healing Actions (Remediation)
#	Task	Why
3.1	Remediation action registry — config/remediation-actions.json mapping failure patterns → safe automated fixes	Define what self-repair is allowed without human approval
3.2	Auto-remediation engine — remediation-engine.js that reads health/sovereignty alerts, matches against registry, executes approved fixes	Turns detection into action
3.3	AI review integration for ambiguous cases — when remediation engine encounters an unmapped failure, auto-escalate to ai-review.sh --auto	Fallback for novel failures
3.4	Retry with exponential backoff — transient failures (Ollama timeout, API 429) auto-retry with backoff + dead-letter queue	Prevents cascading failures
3.5	Governance guard on remediation — any remediation action that touches governance files, keys, or ratified artifacts must escalate to human	Safety boundary
Result: Known failure patterns auto-repair; unknown patterns escalate to AI review or human.
---
Layer 4 — Self-Improvement (Autonomous Convergence)
#	Task	Why
4.1	SwarmMind proposal generator loop — proposal-generator.js that scans for improvement opportunities (stale nodes, schema gaps, untested claims, contradiction clusters) and writes signed proposals to outbox	The idea engine needs to run continuously, not on-demand
4.2	Risk classification engine — risk-classifier.js that tags proposals as LOW/MEDIUM/HIGH based on scope (docs=LOW, schema/config=MEDIUM, keys/governance/deploy=HIGH)	Determines auto-apply vs human-escalate
4.3	Auto-ratification for LOW risk — Archivist auto-ratifies LOW-risk converged proposals, applies changes, commits	Low-risk improvements shouldn't need human bottleneck
4.4	AI-review-gate for MEDIUM risk — converged MEDIUM proposals get AI review before auto-apply	Extra safety layer
4.5	Human escalation queue for HIGH risk — HIGH-risk proposals sit in lanes/archivist/inbox/escalation/ until human or local agent approves	Critical changes need human sign-off
4.6	Implementation executor — post-ratification, auto-implements the change (code generation, file writes, schema updates) with pre-implementation AI review	Closing the loop from proposal → ratified → implemented
Result: System continuously proposes, verifies, ratifies, and implements improvements. Only HIGH-risk changes wait for human.
---
Layer 5 — Oversight Surface (Human/Agent Monitoring)
#	Task	Why
5.1	Status API endpoint — /api/system-health returning live health of all lanes, pending escalations, recent ratifications, active contradictions	Local agent polls this to oversee
5.2	Escalation webhook — POST to configurable URL (n8n, Slack, email) when HIGH-risk proposal awaits or repeated failures detected	You get notified without watching
5.3	Decision drain API — /api/escalations that lets local agent list + approve/reject pending HIGH-risk items	Local agent can intervene programmatically
5.4	Pause/resume mechanism — signal-based (SIGUSR1/SIGUSR2) or API-based pause of individual lane workers or entire system	Emergency stop without SSH
5.5	Oversight summary reporter — daily/weekly markdown report pushed to lanes/broadcast/oversight-report-{date}.md	Audit trail for human review
Result: You or a local agent can monitor, intervene, and audit without being hands-on.
