# 2. File lock gate: make overwrite impossible

Use **atomic lock files**.

Canonical lock directory:

```bash
/home/we4free/agent/locks/
```

Lock file path format:

```bash
/home/we4free/agent/locks/<repo>/<sha256-of-file-path>.lock.json
```

Example lock content:

```json
{
  "lock_id": "kernel-lane:scripts/util/lane-discovery.js",
  "repo": "kernel-lane",
  "path": "scripts/util/lane-discovery.js",
  "owner_agent": "opencode",
  "owner_lane": "kernel",
  "host": "ubuntu-headless",
  "pid": 2607772,
  "created_at": "2026-05-07T19:45:12Z",
  "expires_at": "2026-05-07T20:45:12Z",
  "reason": "fix kernel lane discovery exports",
  "status": "active"
}
```

The rule:

```text
Before any agent writes a file:
1. It must acquire the lock.
2. If the lock exists and is not expired, it must stop.
3. If it cannot acquire the lock, it may write a proposal, not edit the file.
```

Use atomic creation so two agents cannot race:

```bash
mkdir /home/we4free/agent/locks/kernel-lane/scripts.util.lane-discovery.js.lock
```

`mkdir` is atomic on Linux. Only one process wins.

Better than “check then write,” because check-then-write has a race condition.

# Minimal implementation: `store-journal.js`

Create one script in each repo or one shared copy:

```bash

```

Commands:

```bash
node scripts/store-journal.js start \

  --files scripts/util/lane-discovery.js

node scripts/store-journal.js lock \
  --lane kernel \
  --agent opencode \
  --file scripts/util/lane-discovery.js \
  --ttl-minutes 60 \
  --reason "fix kernel lane discovery"

node scripts/store-journal.js complete \
  --lane kernel \
  --agent opencode \
  --target "fix kernel lane discovery" \
  --files scripts/util/lane-discovery.js \
  --result PASS

node scripts/store-journal.js unlock \
  --lane kernel \
  --agent opencode \
  --file scripts/util/lane-discovery.js
```

And preflight:

```bash
node scripts/store-journal.js preflight \
  --lane library \
  --files scripts/runner-v3.sh scripts/post-compact-audit.js
```

Output:

```text
PASS: no active locks
```

or:

```text
BLOCKED: scripts/runner-v3.sh is locked by library/kilo until 2026-05-07T20:45:00Z
```

# Stronger: wrap all writes with `guardWrite`

Since your agents already have `guardWrite` thinking, make the lock gate mandatory.

Instead of agents writing with raw `fs.writeFileSync`, require:

```js
guardWrite({
  repo: "self-organizing-library",
  lane: "library",
  agent: "kilo",
  path: "scripts/store-journal.js",
  reason: "implement store journal",
  content
});
```

`guardWrite` should:

```text
1. Normalize path.
2. Reject paths outside repo.
3. Reject forbidden paths.
4. Check active lock.
5. Acquire lock if requested.
6. Write atomically.
7. Append journal event.
8. Release lock or keep ownership depending on mode.
```

Hard-block direct writes later:

```text
No agent may write source files except through guardWrite / atomicWriteWithLease.
```

# Preventing overwrite across local + headless

This is harder because Windows local and Ubuntu headless are separate filesystems.

You need a **shared lock authority**.

Best options:

## Option A — Headless is lock authority

All agents, including local desktop agents, must SSH to the headless lock service before writing.

```text
Local agent wants to edit S:\self-organizing-library\scripts/foo.js
→ asks headless lock gate for repo/path lock
→ only writes if lock granted
```

This is safest.

## Option B — Git branch ownership

One writer per repo/branch:

```text
headless owns main/source mutation
local desktop is review-only

or

local owns branch feature/x
headless owns branch feature/y
```

This is simpler but less precise.

## Option C — File lock committed to repo

Agents create lock files in:

```bash
.locks/
```

and commit/push them. I do **not** love this because it is slow and creates git noise.
