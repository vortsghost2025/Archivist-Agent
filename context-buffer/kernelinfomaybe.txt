## For headless Ubuntu

```text

- Shell/curl for tests and health checks
```

Your headless agents already run Node services. So the NVIDIA helper should be something like:

```text

```

called by:

```text

```

## For local Windows

Also use **Node + Shell**.

Because your Kilo/OpenCode flow is mostly:

```text
Git Bash / PowerShell
→ bash scripts
→ Node helpers
→ model endpoint
```

So keep the same interface locally and headless:

```bash
bash scripts/ai-review.sh local "..."
bash scripts/ai-review.sh strong "..."
bash scripts/ai-review.sh openrouter "..."
```

The point is: **agents should not care whether the backend is Ollama, NVIDIA, or OpenRouter**. They call the router.

## Best architecture

```text
Agent / lane-worker / Kilo
        ↓
scripts/ai-review.sh
        ↓
local      → Ollama
strong     → NVIDIA NIM via Node/OpenAI SDK
openrouter → OpenRouter via Node/OpenAI SDK
final      → manual human/frontier model
```

That keeps one stable command surface.

## Do not use LangChain yet

LangChain adds another abstraction layer. For your system, that is probably unnecessary right now.

You want:

```text
small, inspectable, auditable scripts
```

not:

```text
framework magic
```

## Important: key hygiene

The screenshot shows an `nvapi-...` key-like value in the code modal. Treat that key as exposed and rotate/revoke it if it is real.

For your scripts, store it only in ignored env files:

```bash
NVIDIA_API_KEY=...
```

Never commit it. Never put it in `ai-review-router.json`.
